## T2 · The live run and the evidence `done 4 Oct, 19:44` `repeat before the presentation`

Done: `docs/report/evidence/` holds a request and response per use case, three agent traces,
two agent-origin rejected plans, the 422 body, the briefing and log excerpts;
`docs/ai-log/2026-10-04-live-run.md` records what happened. To repeat it (for the rehearsal
and on the day):

1. Docker Desktop running; `docker compose up -d`; `docker compose ps` until `healthy`.
2. `.\mvnw.cmd -o clean install` (installs the shared `contracts` jar that a per-module
   `spring-boot:run` resolves from the local Maven repository; `package` alone leaves
   sales-service failing with `ClassNotFoundException: MarkdownAppliedEvent`).
3. Four PowerShell windows, one service each: inventory, pricing, sales, insight. In the insight
   window `$env:LLM_API_KEY` and `$env:LLM_MODEL` must be set; use `gemini-3.5-flash-lite` (verified
   5 October) and never rehearse on the presentation day's model name: the Gemini free tier counts
   requests per model per day, and a spent quota now degrades to 503 `AGENT_UNAVAILABLE` rather than
   failing, but a degraded FR14 is not what you want on stage. Start each with
   `.\mvnw.cmd -o -pl <service> spring-boot:run` and wait for `Started`.
4. `.\scripts\demo.ps1 -TranscriptPath docs\report\evidence\demo-run-transcript.txt`. The
   default rate of 4 sales a minute is what leaves the 400-unit batch at risk; the first risk
   fires about 20 seconds after the first full window closes, the agent answers within 15 s.
5. Read the trace id from the insight console line `[fr14-trace] agentTraceId=TRC-...` and show
   `GET /api/insight/agent-traces/TRC-...`; show `[fr11-rejected]` in the pricing console and
   `GET /api/markdown-plans/MDP-...` for the plan it names.
