## 1. What I did

### 1.1 Verified the three shell facts before changing anything

The authorisation asserted that thirteen commands fail on Windows PowerShell. Rather than take that
on trust and rewrite to match, I reproduced each cause on the machine the run will happen on
(Windows PowerShell **5.1.19041.6456**). All three hold:

| Claim | How it was checked | Result |
|---|---|---|
| `curl` is an alias for `Invoke-WebRequest` | `Get-Alias curl` | `curl` → `Invoke-WebRequest`. `-s -X -H -d` are not its parameters |
| `&&` is not a statement separator | `docker compose ps && docker compose ps` | `The token '&&' is not a valid statement separator in this version` |
| PowerShell strips quotes from native arguments | `python -c "import sys; print(sys.argv[1])" '{"sku":"X"}'` | The program received `{sku:X}` — **not JSON** |

The third is the one that matters most and is the one the authorisation did not name. It is worse
than a parse error, because it **fails silently**: the command runs, curl sends a body, and the
endpoint answers `400` for a reason nothing on screen explains. Escaping every inner quote as `\"`
fixes it, and I verified that too:

```
python -c "import sys; print(sys.argv[1])" '{\"sku\":\"X\",\"quantity\":1}'
  -> {"sku":"X","quantity":1}
```

`curl.exe` resolves to `C:\Windows\system32\curl.exe`, confirmed with `(Get-Command curl.exe).Source`.

### 1.3 Found and fixed four things the authorisation did not list

The authorisation asked me to re-read the whole section for anything else that would fail. Four:

**B2b-F1 — `docker compose down -v && docker compose up -d`.** In the "start from nothing"
blockquote at what was line ~577. `&&` is a parser error in PowerShell 5.1. Now `;`.

**B2b-F2 — the PowerShell sales loop used backtick continuations.** It was already PowerShell, so
it was not in the authorisation's list, but the authorisation also said not to introduce backtick
continuation — and a backtick with trailing whitespace after it is one of the most common ways a
pasted PowerShell block fails, silently changing what the next line means. Rewritten as a
`foreach` whose every statement is complete on its own line.

**B2b-F3 — `docker exec -it` on one-shot commands.** `-t` allocates a TTY and is unnecessary for
`kafka-topics.sh --list` and the two `kafka-consumer-groups.sh` calls; in some PowerShell hosts it
produces `the input device is not a TTY`. Dropped on the four one-shot calls, **kept** on the two
long-running console consumers, which do need a terminal attached. Noted in the text so the
asymmetry does not look accidental.

**B2b-F4 — the bash `date` line was GNU-only.** `date -u -d '+70 minutes'` fails on macOS. Added
the BSD form beside it. This is a bash fix rather than a PowerShell one, and it is in scope for the
same reason: the bash block exists for the teammates who are not on Windows, and half of them are
on macOS.

### 1.5 ADR 0004, amended — team ruling R10

| Where | What |
|---|---|

The Amendment states what the authorisation asked it to state: that the original check was a
**proxy** for the property being protected; that the proxy stopped measuring the property when
LangChain4j became a compile-scope dependency; and that **a check nobody can trust is worse than no
check at all** — because a reviewer who runs it and finds the library on the test classpath will
conclude the ADR has been breached when it has not, and a reviewer who notices it measures nothing
will stop trusting the other three.

The two replacement checks measure the property itself:

- **R10.1** — no test constructs a model client, from configuration or from an API key.
  `MarkdownAgentConfiguration` is `@Profile("!test")` and every test runs under
  `@ActiveProfiles("test")`; the model bean is additionally conditional on a non-empty api key.
- **R10.2** — `mvn test` passes with `LLM_API_KEY` and `LLM_MODEL` unset and with no network access.

Both already held. Nothing about the system changed; what changed is what the ADR claims to check.

The Amendment also records — and does **not** act on — that R10 unblocks the coverage gap B2
reported: a test-source fake `ChatModel` would let the adapter's *use* of the encoder be tested, and
the superseded clause forbade exactly that. It needs its own authorisation, being a code change.

### 1.6 What the four-provider episode is evidence of

Recorded here because it is Section 3 and Section 5 material and because it is the cleanest
available demonstration that ADR 0004 earned its keep.

Between ADR 0004 being written and the first live call being possible, **the LLM configuration was
changed four times**:

| # | What happened | Where the fix landed |
|---|---|---|
| 1 | The first model name resolved to an **empty environment variable** | The environment |
| 2 | The second was **withdrawn from new users by the vendor** — the API answered `404 ... is no longer available to new users` | The environment |
| 3 | The third **exceeded a quota** | The environment |
| 4 | The fourth worked | — |

The provider's commercial terms also moved under the project: the vendor's free tier stopped being
available to a project **the moment a billing account was linked to it**, which is a change nobody
on the team made, asked for, or could have planned against.

**The cost of all of that to the codebase was zero.** That claim is falsifiable, and here is how a
reader checks it:

```
$ git log --oneline -S'gemini' -- '*.java'
(no output — no .java file has ever contained a model name, in any commit)

$ git log --oneline f8ea1af..HEAD -- 'insight-service/src/**/*.java'
cef488a feat: FR14 Phase B2 runtime wiring, LangChain4j adapter and R7/R8/R9
0e20e29 feat: implement FR14 Phase B1 so the nine failing tests pass
6f4ae77 test: FR14 Phase A type surface and failing tests
```

Three commits touch Java since ADR 0004 (`f8ea1af`), and each is a scheduled FR14 phase — Phase A's
type surface, Phase B1's method bodies, Phase B2's adapters. **None of them is a response to a
provider change**, and this phase, B2b, touches no Java at all. `application.yml` names
`${LLM_PROVIDER}`, `${LLM_MODEL}` and `${LLM_API_KEY}` and never a value:

```
145:    provider: ${LLM_PROVIDER:google-ai-gemini}
146:    model: ${LLM_MODEL:}
147:    api-key: ${LLM_API_KEY:}
```

**The general point, for the report.** ADR 0004 was argued on testability — an LLM is
non-deterministic, remote, paid for and credentialled, so everything FR14 must get right belongs on
the near side of a port. The episode above exercised a property the ADR did not claim and gets for
free: a supplier's commercial decision reached this system as a **configuration event** rather than
a rewrite. spec-01 §2.7 asked for the provider to be injectable "so hosted API and local Ollama are
interchangeable without code change", and the clause turned out to be load-bearing for a reason
nobody wrote down — not for swapping to Ollama, but for surviving four changes of mind by a vendor
inside a fortnight.

Worth saying plainly in the report, because it is the difference between an architectural argument
that was asserted and one that was **tested by events**.

## 4. Where I judged something wrong — flagged, NOT acted on

**4.1 — the `curl.exe` escaping is correct and unreadable, and both are true.**
`-d '{\"sku\":\"SKU-YOG-1KG\",...}'` is what PowerShell 5.1 requires and it is hostile to read and to
retype. Two better options exist and both were out of scope: keep the JSON bodies in files next to
the runbook and use `-d "@batch.json"`, which is readable, diffable and identical in both shells; or
drop `curl.exe` and use `Invoke-RestMethod` throughout, which needs no escaping but then reads
nothing like the bash form a teammate is running. **The file-based form is my recommendation** if
this section is used more than once. Not acted on: it adds files to the repository, which is beyond
"documentation only".

**4.2 — PowerShell 7 would make most of this section unnecessary.** It has `&&`, it does not mangle
native arguments the same way, and `curl` is not aliased. The machine recording the demonstration
runs 5.1, so the correction targets 5.1; a note that upgrading the shell removes a whole class of
failure is worth the team's attention before the video is recorded, not after. **Flagged.**

**4.3 — Part B3 has never been executed, and this phase did not change that.** Every command is now
syntactically valid for the shell it is labelled with, which is a smaller claim than "it works". The
three things B2 said it could not verify — the Jackson version skew, the message-channel consumer
reading the Kafka Streams producer's output, and whether the model calls tools at all — are all
still unverified.
