## 1. What happened, in order

**First attempt, 19:34.** Four services started with `.\mvnw.cmd -pl <service> spring-boot:run`.
sales-service failed with `ClassNotFoundException: com.freshflow.contracts.MarkdownAppliedEvent`,
and inventory-service answered 500 on `POST /api/batches` with
`NoClassDefFoundError: com/freshflow/contracts/MoneyPayload`. Cause: a per-module
`spring-boot:run` resolves `contracts` from the local Maven repository, where the installed jar
dated from before Week 6. The earlier runs in September had been preceded by `mvnw install`;
the README written this afternoon said `package`. Fix: `.\mvnw.cmd -o -pl contracts install`,
README and roadmap changed to `clean install`, all four JVMs stopped (the first attempt to stop
only pricing killed the Maven launcher and left the forked Boot JVM holding port 8083), the
Kafka container recreated for a clean slate, and the Kafka Streams state directory cleared.

**Second attempt, 19:44.** `.\scripts\demo.ps1 -Rate 4 -DurationSeconds 150`. Four sales a
minute is deliberate: the RUNBOOK's arithmetic says a 400-unit batch with one hour left is
flagged only while the velocity stays under about 395 units an hour, and the script's earlier
default of 30 a minute would have cleared it.

## 3. Deviations

- `scripts/demo.ps1` default rate changed from 30 to 4 a minute, and a `-TranscriptPath` option
  added, because `Write-Host` output does not reach `Tee-Object`; the first capture held only
  the simulator's lines and the per-use-case JSON files were reconstructed from the session's
  own console output.
- README and roadmap now say `clean install`, not `clean package`.

## 4. Observations not acted on

- Four `[detected]` events produced three traces inside the run window; the fourth
  (`6b137f43`) arrived while the single-threaded agent consumer was busy and was not
  deliberated before the capture ended. Worth a look at whether it was deliberated afterwards.
- The `[fr11-rejected]` outcome for both agent proposals shows the central argument working,
  but it also shows that PERCENT_50 is never acceptable for either seeded SKU. A demonstration
  that wants to show an *accepted* agent proposal would seed a SKU with a lower floor or a
  higher base price.
- Gemini accepted the parameterless `listCurrentRisks` tool specification and finished the
  briefing in three calls; `max-steps` 8 was not approached.
